# CLAUDE.md, docs/

The read-only reference layer of the BMAI HS26 weekend-1 scratch repository. Nothing here ships to
a participant. Everything here exists so that the same source is never re-read from scratch.

Start at the repository root `CLAUDE.md` for the course, the schedule and the house rules.

## What is here

```
docs/
  CLAUDE.md                      this file
  master-schedule-weekend1.csv   the weekend-1 tab of the master spreadsheet, downloaded
  slide-text-extracts/           pdftotext output for the four root PDFs, 8208 lines
  summaries/                     seven reference documents from the review phase, 7473 lines
```

Neither subdirectory carries a nested `CLAUDE.md`. Both are indexed file by file in the tables
below, and neither holds a decision of its own: `slide-text-extracts/` is machine output that is
regenerated by one command, and `summaries/` is a set of dated documents that each state their own
sources at the head. If a subdirectory here ever starts holding decisions, give it its own
`CLAUDE.md` at that moment, with the maintenance contract at the foot of this file.

schedule says about weekend 1, those three rows included, is transcribed into the root `CLAUDE.md`.
Re-download this file rather than editing it, and update the root table in the same commit.

The far-right column of the sheet carries links that belong to no timetable row: the Overleaf
teaching plan https://www.overleaf.com/6246534572rhwckvrwdzgz#c494bd , the FS26 GitLab repository
https://gitlab.ethz.ch/bmai/cx/2026fs , and a BMAI meetings calendar `.ics`.

## `slide-text-extracts/`

`pdftotext -layout` output for the four PDFs at the repository root. They exist for grep and for
quoting printed slides.

| File | Lines | Source PDF |
|---|---|---|
| `bmai_w1_sml_annotated__1_.txt` | 1257 | `bmai_w1_sml_annotated (1).pdf` , 60 pages |
| `bmai_w1_robbins_monro_gradient_descent__1_.txt` | 52 | `bmai_w1_robbins_monro_gradient_descent (1).pdf` , 1 page |
| `ainit_rl-slides.txt` | 3160 | `ainit_rl-slides.pdf` , 191 pages |
| `ainit_annotated_rl_slides__1_.txt` | 3739 | `ainit_annotated_rl_slides (1).pdf` , 205 pages |

Three things to know before trusting an extract:

1. **The handwritten pages are unusable.** Pages 27 to 46 and 49 to 51 of the SLT deck are
   handwritten, and OCR of them is noise. To read them, render the page at 150 dpi and look at the
   image. `docs/summaries/04` did exactly that and quotes the result.
2. **The one-page hand diagram extracts as garbage.** The 52 lines of
   `bmai_w1_robbins_monro_gradient_descent__1_.txt` are a scrambled reading of a diagram whose whole
   meaning is its layout, including the misspelling "Scientifie". Read the PDF page as an image.
3. **The AINIT PDFs in this repository are an older build.** The current deck in
   `/Users/carloscotrini/Documents/git_ainit/rl-arcade/slides/rl-slides.pdf` is 234 pages and 51
   numbered frames; the copy here is 191 pages and 43 frames. The difference is a six-frame REINFORCE
   coda added on 2026-06-20, and the extract contains zero occurrences of "REINFORCE", which confirms
   it. The Faust cold open and the genie material are identical in both, so nothing depends on the
   discrepancy. Do not size the deck off the extract.

To regenerate, from the repository root:

```
pdftotext -layout "bmai_w1_sml_annotated (1).pdf" docs/slide-text-extracts/bmai_w1_sml_annotated__1_.txt
```

Rendering a page as an image, which is how the handwritten pages must be read:

```
pdftoppm -png -r 150 -f 28 -l 34 "bmai_w1_sml_annotated (1).pdf" /tmp/slt
```

### How to use them

- Designing an exercise: `04` for what the lecture needs, then `05` section 4 for what to fork,
  then the matching file in `proposals/`.
- Building a visualization: `00` section 2 for the standard, `06` for the shell to copy,
  `01` for how a sibling course solved the same problem.
- Building a notebook: `03`, then `initial-states/hs26-bmai-w1-opt-rm-house/` as the worked example.
- Writing a deck or a cold open: `00` section 3, then `02`, then the FDD cold-open menus named in
  the root `CLAUDE.md`, then `initial-states/cold-open-weekend1/` as the built weekend-1 answer.

### Two standing cautions

- A summary is a snapshot of what was on disk on 2026-08-26. Where its wording is load-bearing it
  quotes the source and names the file and line. Where exact wording matters to a decision, open the
  source. Two of the summaries have since been overtaken in one respect: `05` and `06` were
  written before anything under `initial-states/` existed, so where they speak about what should be
  built, the built directory is now the authority.
- These files use ASCII punctuation throughout, including where the source they quote uses an em
  dash. `00` states that substitution policy at its head and flags it at each occurrence.

## Maintenance contract

- This file is the working memory for this directory. After any major change here, meaning a new
  summary or extract, a re-downloaded schedule, a renamed or moved file, a changed extraction
  command, or a change in who owns the work, UPDATE THIS FILE IN THE SAME COMMIT. A CLAUDE.md that
  describes a layout the directory no longer has is worse than none.
- Every subdirectory that holds work of its own carries its own CLAUDE.md, and that file must
  itself carry this same maintenance contract, including this propagation rule. When you create a
  subdirectory, create its CLAUDE.md at the same time. The two subdirectories here are the
  documented exception explained at the top of this file, and that exception is stated in writing
  rather than assumed.
- Keep it concrete: real file names, real identifiers, real commands. Record the gotchas that cost
  someone an hour. Do not restate what the code already says plainly.
